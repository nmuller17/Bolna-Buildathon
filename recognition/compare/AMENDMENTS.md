11. **Epoch-cap sensitivity analysis (declared now, run before the primary is read where compute allows, reported next to the primary).** The protocol caps every network at 60 epochs. The winner's notebook trains for 300 epochs (late dropout from epoch 15), so the nested rule with a 60-epoch cap can only shorten `islr1st_retrained`. Sensitivity run: the identical nested rule (inner-signer validation loss, patience 12, temperature on the inner signer, refit for the chosen epochs) with a **200-epoch cap**, for `ours_gru` (cheap, run first, keeps the comparison symmetric), then `islr1st_retrained`, then `islr1st_ourfeat` if compute allows. 200 rather than 300 because of CPU time on a shared machine; with about 1,200 training clips (19 steps per epoch) it already allows about 3,800 optimisation steps.

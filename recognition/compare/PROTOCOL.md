# Pre-registered comparison protocol, Track A v1 (and Track B rules)

Written on 2026-10-10, before any run under it. The question: on the same held-out Deaf signers and the same clips, is our product classifier (`ours_gru`) as accurate as the GISLR 1st-place recipe trained on exactly the same data, and how often does each system speak a wrong sign?

This file is hashed. Every run records its sha256 in its manifest, and the report accepts only results whose manifest matches the current file. **Do not edit this file after the re-run starts.** Corrections after that point go in `AMENDMENTS.md`, with the date, the reason, and whether any result had been seen. Approval: Talha must review this file before the re-run is launched. If he changes anything, the sha256 changes and the new value is recorded in the progress notes before launch.

## 1. Test data (fixed)

- **Source.** The GISLR rerun set (Kaggle `sohier/461054610546105`). It is the competition's hidden test set, and Kaggle's metadata lists it as CC0. Our conversion is in `data/gislr/`, `data/gislr_oov/` and `data/gislr_raw/`.
- **Signers.** There are 10 participant IDs: 2455, 6927, 11672, 11696, 14938, 15662, 23662, 32536, 34304 and 48118. Kaggle's public leaderboard used 6927, 11696, 14938 and 23662. The private leaderboard used the other 6.
- **In-vocabulary clips.** There are 1,105 clips of the 7 signs our vocabulary shares with GISLR: YES, NO, THANK-YOU, WHERE, TIME, PLEASE and ROOM.
- **Outside-vocabulary clips.** There are 450 clips of 30 other GISLR signs, 15 clips per sign. A seed-0 permutation, already fixed, splits these signs into two halves:
  - `NONE_TRAIN` (used only to train NONE): bird, book, cat, cow, dance, drink, elephant, happy, horse, lion, pig, sad, scissors, tree, zipper;
  - `NONE_TEST` (used only for the open-set test): airplane, apple, cloud, cry, dog, fish, flower, frog, girl, hat, jump, kiss, mom, rain, shirt.
- **Index fingerprint.** The clip index fingerprint is `8626d72cf79d5bc86b7b5bc0ae47f30159333ce0523f3fa3824f2228e6039aca`. It is computed by `manifest.index_fingerprint`, which covers every clip's ID, signer, label, outside flag and GISLR sign, plus the NONE split. The runner refuses any other index.
- **Folds.** There are 10 outer folds, leave-one-signer-out. Fold *s* trains on every clip of the other 9 signers: their 7-sign clips plus their `NONE_TRAIN` clips. It tests on signer *s*'s 7-sign clips and on signer *s*'s `NONE_TEST` clips. These are 225 open-set clips in total over the 10 folds.

## 2. Systems and their roles

| system | role | what it is |
|---|---|---|
| `ours_gru` | **compared (product)** | SignGRU with our 141 features and our training code (`recognition/train.py`) |
| `islr1st_retrained` | **compared (competitor recipe)** | The GISLR 1st-place network with its own preprocessing (130 points), augmentation and optimiser (ported in `islr1st.py`), trained from scratch on exactly our folds. It uses 1 seed, no AWP and the CPU. |
| `islr1st_ourfeat` | compared (secondary) | The 1st-place network inside our training code with our features: only the architecture differs from `ours_gru` |
| `ours_baseline` | compared (secondary) | Our logistic-regression fallback |
| `islr1st_pretrained` | **reference only** | The published 1st-place TFLite weights (sha256 `f55a2bb1…`, a 3-seed ensemble), not retrained |

**The pretrained reference.** The retrained systems and the pretrained reference were not trained under the same conditions, for four reasons:
- The reference was trained on 94,477 clips of 250 signs from 21 participant IDs. None of these IDs is one of our 10 test IDs, but we have not verified that different IDs are always different people.
- The winner's model selection used the public leaderboard, which is 4 of our test signers.
- Its training vocabulary contains all 30 outside signs.

It is therefore labelled "a much larger model trained on more signers, with signer-disjoint IDs (identity unverified)" and reported in a separate section. It is **excluded from every outside-vocabulary or false-accept comparison and from every paired test**. It is not described as an upper bound or as a fair comparison.

## 3. Equal exposure

- **Training clips.** Every compared system trains on the identical clip list for each fold. Each manifest records the sha256 of the training clip-ID list, and the report checks it against the protocol fold.
- **Inner split.** Every compared system uses one identical inner split per fold, produced by `inner_split`: `recognition.train.split` over the fold's 9 training signers, with seed 0.
- **Outside signs.** No compared system ever sees a `NONE_TEST` sign or the outer test signer. Both are checked in every manifest.
- **Landmarks.** All systems read the same GISLR MediaPipe landmarks. The only difference is how each one preprocesses them, which is part of its recipe.

## 4. Training and tuning (nested; no global pilot)

- **Networks.** This covers `ours_gru`, `islr1st_ourfeat` and `islr1st_retrained`. Inside each outer fold:
  1. Train on the 8 inner-training signers for at most **60 epochs**.
  2. After every epoch, compute the inner validation signer's unaugmented cross-entropy loss. Keep the epoch with the lowest loss; an improvement must be greater than 1e-4.
  3. Stop after **12 epochs** without improvement.
  4. Fit the temperature on the inner validation signer with `recognition.model.fit_temperature`. It may only soften the model (T >= 1).
  5. Refit on all 9 training signers for the chosen number of epochs. The learning-rate schedule spans those epochs.
  6. Apply the inner temperature to the refitted model.

  This is the procedure `recognition.benchmark` already uses for our model. `islr1st_retrained` now uses it too. The old fixed 60 epochs from the global pilot are not used, and the pilot is deleted from the code.
- **`ours_baseline`.** It has no epochs. Its temperature is fitted on the inner validation signer, and it is then refitted on all 9 training signers.
- **Fixed settings.** All other hyper-parameters are fixed in the code as it stands at this protocol's sha256, and no hyper-parameter is chosen by looking at an outer test signer:
  - our learning rate 2e-3;
  - the winner's AdamW 5e-4, weight decay 0.1, label smoothing 0.1, late dropout from epoch 15;
  - batch 64;
  - seed 0;
  - 2 torch threads per job, `OMP_NUM_THREADS=2`.
- **Reproducibility tolerance.** A repeat of `ours_baseline` on fold 2455 reproduced every top-1 answer and every accept-or-reject decision. Its confidences moved by up to 1.6e-3 because the temperature fit is not bit-reproducible. Results are reproducible at that level, not bit for bit.

## 5. Rejection rule (fixed a priori)

- **Product rule.** It applies to every compared system in R8: speak the top-1 sign only when its confidence is >= 0.6 and it is not NONE. Otherwise the guest is asked to repeat. A confident NONE is never a spoken sign.
- **C7 (forced choice).** The 8-way distribution is renormalised over the 7 signs. Coverage and accuracy@0.6 use the same 0.6 threshold.
- **Alternative rules.** No other rejection rule or threshold is pre-registered for the compared systems. Any alternative may only be chosen on inner validation signers, never on outer test folds, and must be added through `AMENDMENTS.md` before it is scored.
- **Pretrained R8 (pre-specified).** Use the **sum rule**: NONE = the total probability of its 243 other signs. The 8 values are then its own 250-way probabilities collapsed onto our labels, and they sum to 1.
- **Max-other rule.** This rule (NONE = probability of its best other sign) was chosen after results had been seen. It is written only to `preds_exploratory/` and may only be shown labelled "post hoc, exploratory".

## 6. Endpoints

Every number is reported with:
- the test set;
- the number of signers;
- the number of clips;
- whether the signers were held out;
- a 95% CI computed over signers.

**Primary.** The C7 top-1 accuracy difference `ours_gru` minus `islr1st_retrained`. It uses all 10 outer folds: 10 signers and 1,105 in-vocabulary clips, all held out. C7 is primary because it measures sign discrimination on its own, separate from how each recipe learns NONE.

**Decision rule for the primary.** The 95% signer-bootstrap CI of the difference is read as follows:
- lower bound > 0: "ours better";
- upper bound < 0: "ours worse";
- otherwise, lower bound > −0.05: "not worse by more than 5 percentage points; no detectable difference";
- otherwise: "inconclusive".

The −0.05 margin is fixed here and must be confirmed by Talha before launch. No other result changes the verdict.

**Secondary.** These are descriptive, with no multiplicity correction and no verdicts:
- R8 top-1 accuracy;
- open-set false accept (R8, product rule, 225 `NONE_TEST` clips);
- coverage@0.6, accuracy@0.6 and wrong-sign-spoken rate;
- macro-F1, per-class recall and confusion matrices;
- per-signer accuracy.

They are reported for all 4 compared systems in both modes. Paired tests are run for `ours_gru` against each other compared system, and for `ours_baseline` against the two winner-network systems.

**Sensitivity.**
- The same tables on only the 6 private-leaderboard signers (737 in-vocabulary clips), whose clips could not have influenced the published winner.
- The pretrained reference on all 10 signers and on the private 6, in C7 and R8 (sum rule).

**Exploratory, labelled as such.**
- The pretrained R8 max-other rule.
- The 22-output argmax check for our models.
- Anything in `oov_strata.py`, which is a separate stratified outside-sign study prepared in parallel and not part of this protocol unless it is added by an amendment before it is scored.

## 7. Statistics

- **Confidence intervals.** 95% CIs come from a percentile bootstrap over **signers**, with B = 2,000 and seed 0. Each draw resamples signers with replacement and pools their clips, because clips of one person are not independent.
- **Paired comparisons.** They use identical clips: the difference, its signer-bootstrap CI, and a two-sided signer-bootstrap p. The exact McNemar p on top-1 is shown, but it is optimistic because it treats clips as independent.
- **Low power.** With 10 signers the CIs are wide. A non-significant difference is not evidence of equality unless the CI excludes the margin.

## 8. Manifests and refusal

Each (system, fold) job writes `preds/<system>_<fold>.manifest.json` after its predictions. It records:
- the protocol sha256 and the index fingerprint;
- the train, inner-train, inner-validation and test signer IDs;
- the sha256 of the clip-ID lists and the counts per label;
- the training signs used for NONE;
- the seed, maximum epochs, best epoch, epochs run and temperature, with the rules that chose them;
- the sha256 of every `recognition/compare/*.py` file and of `recognition/{features,model,train,data,labels,benchmark}.py`;
- the git commit and the modified tracked files;
- the library versions;
- the start and end time with the machine load;
- the sha256 of every output file.

`report.py` refuses a system whenever any of the following holds:
- any fold lacks a manifest;
- a manifest names a different protocol or index;
- a manifest is a smoke test;
- a manifest's fold data differs from the protocol fold, which covers unequal exposure, a `NONE_TEST` sign in training, and the outer signer in training or inner validation;
- epochs were not chosen by the nested rule;
- an output file changed after its manifest was written;
- the training-code hashes differ between the manifests combined in one report.

**Legacy runs.** The runs in `data/compare/track_a/` have no manifests. They are exploratory and are never reported under this protocol.

## 9. Run procedure

1. Run `ps aux | grep recognition`. Never start a duplicate run.
2. Run `python -m recognition.compare.track_a_gislr index`. It must print the fingerprint above.
3. Run `python -m recognition.compare.track_a_gislr run --workers 5`.
   - It uses at most 6 workers and 2 threads each.
   - It writes `run.pid` and refuses to start if that file exists.
   - It kills its children on failure.
   - It resumes by skipping jobs whose manifest still validates.
4. Run `python -m recognition.compare.track_a_gislr pretrained`. It re-runs the TFLite model in the bench venv and writes a manifest with the sum rule.
5. Run `python -m recognition.compare.report --track a`. It writes `reports/track_a_v1.md` and `.json`.
6. Measure latency only on an idle machine, with `latency`, which refuses to run when the 1-minute load is above 2. Latency is not part of any accuracy claim.

## 10. Track B (our 22 classes; awaiting real held-out recordings)

**Our models.** They use the live path for one sign, as follows:
1. HolisticLandmarker runs in VIDEO mode with the pinned `.task` file.
2. `FrameAdapter(mode="capture", image_size=(w, h))` produces `capture/landmarks.py` `to_frame(result, w / h)` plus `normalize`, with face data minimised as live does.
3. The framing gate (`framing.check` per frame; at least 80% OK over the hand-visible span) is applied, with waist "hips".
4. `capture.clean.clean(frames, capture times in ms)` is applied, keeping at most 300 frames.
5. `Recognizer.predict` gives the answer. It includes the model hash pin, validation, and NONE when there are not enough hands or pose.

**Unspoken clips.** A clip the live path would not speak (no hands, framing rejected) counts as NONE with confidence 0.

**Checks and variants.** A unit test checks these frames against `capture.py`'s processing of the same MediaPipe results. Running without the framing gate is a sensitivity analysis only. Each run writes a manifest with the checkpoint sha256, the gate settings, the outcome counts and the prediction sha256. The report refuses our rows without it.

**Other systems.** The Claude-vision baseline and the manual competitor importer are unchanged. They are scored on the clips every system answered, and each system's no-answer rate is reported.

**When a result exists.** No Track B result exists until held-out signers record clips under the README protocol:
- consent;
- the demo setup;
- a model frozen and hashed before recording;
- no test clip in `data/train/`.

The same endpoints and statistics apply: top-1 accuracy, wrong-sign-spoken rate and false accept, each with signer CIs.

## 11. What this protocol cannot fix

- The pretrained model's outside-vocabulary result. A matched test needs signs outside all 250 GISLR signs, which means new data.
- Proof that GISLR participant IDs are distinct people.
- Track A does not test the live segmenter or the 22-class vocabulary. That is Track B's job.
